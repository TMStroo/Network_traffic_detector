# NetworkTrafficAnalyzer

Reads PCAP network captures and finds unusual communication patterns.

It parses Ethernet, IPv4, IPv6, TCP, UDP, DNS and HTTP metadata, reconstructs
network conversations, groups communication by host, builds timelines of
network activity, correlates information across multiple captures, and
explains why each detected event deserves investigation.

## Stack

- C++20: main application, packet processing, flow tracking, detection engine
- SQLite: persistent storage and correlation across captures
- Python 3: statistical analysis (`python/nta_stats.py`)
- Scapy (optional): independent PCAP/PCAPNG inspection and validation (`tools/validate_pcap.py`)
- CMake + Unix Makefiles: build system

## Build

```sh
cmake -S . -B build -G "Unix Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
```

Produces the `nta` executable in `build/`.

## Usage

All commands take `--db PATH` (default `analyze.db`).

```sh
# Read captures and store everything (packets, hosts, conversations,
# DNS queries, HTTP events, anomalies). Accepts several pcaps.
./build/nta analyze tests/sample.pcap --db analyze.db --reset

# Inspect stored data.
./build/nta hosts --db analyze.db --host 10.0.0.5
./build/nta conversations --db analyze.db --protocol udp --limit 10
./build/nta conversations --db analyze.db --protocol tcp

# Activity timeline. Options: --host, --since, --until, --limit.
./build/nta timeline --db analyze.db --host 10.0.0.5 --limit 50

# DNS queries and responses.
./build/nta dns --db analyze.db --host 8.8.8.8

# Anomalies found. Options: --type, --min-conf.
./build/nta anomalies --db analyze.db

# JSON statistical summary (via the Python module).
./build/nta stats --db analyze.db

# Full report: hosts, conversations, anomalies, timeline, stats.
./build/nta report --db analyze.db

# Cross-capture correlation: hosts and conversation pairs seen in
# more than one capture of the same database.
./build/nta correlate --db analyze.db
```

### Detectors

Each anomaly has evidence and an explanation of why it deserves
investigation. Detectors include:

- `dns_tunneling` - host sends many unique DNS names with long labels
- `dns_high_nxdomain` - host sends many NXDOMAIN responses
- `port_scan` - source dials many destination ports on one host in a short window
- `beaconing` - regular, periodic traffic between the same hosts
- `data_exfil` - large internal-to-external transfers and uncommon-port bulk data
- `http_errors` - burst of 404/5xx responses on one host pair
- `unusual_protocol_port` - non-TCP/UDP protocols on uncommon ports

## Project structure

```
src/
  main.cpp            CLI commands
  cli.h/.cpp          argument parser
  pcap.h/.cpp         classic libpcap file reader
  packet.h/.cpp       Ethernet/IPv4/IPv6/TCP/UDP/DNS/HTTP parsing
  conversation.h/.cpp conversation tracker with TCP reassembly
  storage.h/.cpp      SQLite wrapper, schema, insert and query methods
  detector.h/.cpp     anomaly detectors
  timeline.h/.cpp     activity timeline builder
  python_stats.h/.cpp runs the Python statistics module
  correlator.h/.cpp   cross-capture correlation
  sqlite3.h           minimal SQLite C API header
python/nta_stats.py   statistical analysis module (JSON report)
tools/gen_test_pcap.py  synthetic PCAP generator with normal traffic and anomalies
tests/sample.pcap     sample capture generated by the tool
```

## Testing

Generate the sample capture and analyze it:

```sh
python3 tools/gen_test_pcap.py -o tests/sample.pcap
./build/nta analyze tests/sample.pcap --db tests/analyze.db --reset
./build/nta anomalies --db tests/analyze.db
```

Scapy is optional. Install it when you want an independent check of the
capture file and its protocol layers:

```sh
python3 -m pip install scapy
python3 tools/validate_pcap.py tests/sample.pcap
```

Scapy is not used by the C++ parser. Keeping the parser in C++ makes packet
handling part of the project rather than hiding it behind a library. Scapy
provides a second view of the same capture, which helps compare packet and
protocol counts.

`tools/gen_test_pcap.py` generates normal DNS and web traffic plus a few
injected scenarios (beaconing, port scan, DNS tunneling, data exfiltration,
HTTP errors, IPv6 traffic).
